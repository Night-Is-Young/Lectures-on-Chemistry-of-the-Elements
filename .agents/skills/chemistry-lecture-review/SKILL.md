# 元素化学讲义审阅

产出有证据、可定位、可落实的审阅结果，区分确定错误、待核查判断与教学建议。尊重用户指定的范围和审阅深度。

## 项目范围检查

- 本技能只适用于承载其自身 .agents/skills/chemistry-lecture-review/ 目录的项目。开始工作前，确定技能所在 .agents 目录的父目录，并确认它就是当前活动工作区或当前 Git 仓库的根目录。
- 若当前任务位于另一个项目、项目外目录，或无法确认活动项目与技能所属项目相同，立即停止使用本技能，并说明它仅限所属的元素化学讲义项目。即使用户在其他项目中显式点名本技能，也不得据此继续。
- 不得把本技能复制、安装或注册到用户级、系统级或其他项目的技能目录，除非用户另行明确要求改变作用域。

## 修改前必须备份

- 对任何已有文件执行修改、覆盖、替换、重命名或删除前，必须先保存其当时的完整备份；包括正文、参考文献、图片及图源、样式、配置、技能文件，以及工具或编译过程可能覆盖的已有输出。不得未保存原稿就直接修改。
- 备份使用独立且唯一的时间戳路径，保留原文件名和必要的目录关系；不得覆盖或自动清理旧备份。每次再次修改前，都应保存紧邻该次修改前的版本。
- 先完成备份并验证副本与原文件内容一致（例如比较 SHA-256），再执行修改。备份失败或无法验证时，停止对该文件的写入并说明原因；已有 Git 历史或旧备份不能代替这次修改前的备份。
- 批量操作先备份全部将受影响的已有文件；编译、转换等操作优先在新的独立目录中进行，若会覆盖已有文件同样先备份。全新文件没有旧版可备份，但须确认目标不存在，防止意外覆盖。
- 交付时说明备份位置，使用户能够找回修改前的原稿。

## 确定范围

- 阅读 [项目地图](references/project.md) 和 [核查方法与案例](references/review.md)。读取目标正文及与问题直接相关的图题、数据、习题、答案和引文。
- 仅请求审阅时不修改讲义、参考文献、图片或共用样式。可在临时目录做计算、编译或生成审阅报告。明确要求“审阅并修正”时按已有授权落实，不反复征求确认；写作技能存在时可用于改写，否则独立完成。
- 局部检查不扩展为全书审计。范围大到只能分批时说明已覆盖部分与剩余部分，不能将抽查说成全面核验。

## 核查过程

1. 先检查文内可判定的问题：元素与电荷守恒、公式等价关系、单位、化学式与氧化态、图文和题文冲突、复制残留、引用定位。
2. 按论断查证外部证据。优先影响结论或解题的结构、反应条件、物种身份、数据和推导；对知识性争议查原始研究，依实际证据分类。
3. 检查论证：事实是否支持所述原因，是否混淆热力学和动力学、分子与固相、理论预测和实验实现、氧化态和电荷。不同模型可能适用于不同层级，不因模型简化就判错。
4. 检查教学连贯性和习题可解性。承认有意的跨章节安排和扩展题；用计算或推导验证可疑题目，而非只凭语言判断。
5. 必要时在临时副本编译并查看 PDF 图表；排版通过与科学准确性是不同的验证结果。

## 输出

先报告影响学习或解题的主要发现。每个实质问题包含：

- 文件与准确位置，足以定位的短原文或公式。
- 问题及影响：具体说明错误或证据缺口在哪里。
- 证据状态：文内可确定／外部来源支持／待核查／教学建议。
- 建议改法：证据足够时给出最小替换文字或公式；不确定时给出需要核对的来源或条件，不擅自确定答案。

优先级与确定程度分开：严重影响概念或答案的优先，其次是局部科学错误，再次是清晰度和排版。合并同源问题，避免一条笔误拆成多个发现。问题少时用短列表，多时用表格；不要强制生成空类别。

结尾简述阅读、查证、计算和排版验证实际覆盖的范围及未能确认的关键点。没有发现问题时明确说明，但不把“未发现”表述为已证明整章无误。

## 与写作技能的关系

本技能默认交付审阅意见和必要的示例改法；整段重写和新主题增补由 chemistry-lecture-writing 承担。两者独立可用，不自动相互调用或启动代理。
