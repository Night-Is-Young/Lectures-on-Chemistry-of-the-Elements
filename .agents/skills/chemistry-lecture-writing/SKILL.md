# 元素化学讲义写作

为这套中文元素化学讲义产出可以直接采用的内容。用户指定的读者、深度、范围和输出形式优先于以下从现有讲义提炼的惯例。

## 项目范围检查

- 本技能只适用于承载其自身 .agents/skills/chemistry-lecture-writing/ 目录的项目。开始工作前，确定技能所在 .agents 目录的父目录，并确认它就是当前活动工作区或当前 Git 仓库的根目录。
- 若当前任务位于另一个项目、项目外目录，或无法确认活动项目与技能所属项目相同，立即停止使用本技能，并说明它仅限所属的元素化学讲义项目。即使用户在其他项目中显式点名本技能，也不得据此继续。
- 不得把本技能复制、安装或注册到用户级、系统级或其他项目的技能目录，除非用户另行明确要求改变作用域。

## 修改前必须备份

- 对任何已有文件执行修改、覆盖、替换、重命名或删除前，必须先保存其当时的完整备份；包括正文、参考文献、图片及图源、样式、配置、技能文件，以及工具或编译过程可能覆盖的已有输出。不得未保存原稿就直接修改。
- 备份使用独立且唯一的时间戳路径，保留原文件名和必要的目录关系；不得覆盖或自动清理旧备份。每次再次修改前，都应保存紧邻该次修改前的版本。
- 先完成备份并验证副本与原文件内容一致（例如比较 SHA-256），再执行修改。备份失败或无法验证时，停止对该文件的写入并说明原因；已有 Git 历史或旧备份不能代替这次修改前的备份。
- 批量操作先备份全部将受影响的已有文件；编译、转换等操作优先在新的独立目录中进行，若会覆盖已有文件同样先备份。全新文件没有旧版可备份，但须确认目标不存在，防止意外覆盖。
- 交付时说明备份位置，使用户能够找回修改前的原稿。

## 开始工作

- 阅读 [项目与 LaTeX 约定](references/project.md)，定位实际文件；路径失效时在当前项目中重新查找。
- 阅读 [写作与证据规则](references/writing.md)，然后读取目标小节、相邻段落、相关图题与习题。跨族主题只追踪必要的关联章节。
- “给出正文／草稿”按要求交付文字；“修改／补写讲义”先按下述备份规则保存原稿，再编辑对应源码。请求明确时不要增加逐步审批。缺少影响正确性的必要条件才提问。
- 修订清单是输入而非已验证事实：对影响科学结论的建议检查其依据；保留用户正在进行的其它修改。

## 写作过程

1. 确定本段的教学问题与插入位置。先判断内容在别处是否已有安排，避免重复。新增专论说明它与前后内容的联系。
2. 为需要外部依据的新增或改动论断查证来源，记录原文位置、条件和证据类型；按 writing.md 处理事实、模型和作者解释。
3. 形成连贯正文：以现象或问题引入，给出必要的结构或数据，解释性质或反应，说明边界。顺序随主题调整，不强制每种物质套用同一模板。
4. 只在解释需要时增加图表或习题。科学结构图须有数据或明确模型依据。习题需检查条件充分性并实际求解；是否附答案遵从用户要求。
5. 保留现有宏接口、图源、引用键和标题层级。改动事实后同步检查直接相关的表格、图题、交叉引用、习题及答案。

## 完成检查与交付

- 自查新增／改动内容的元素与电荷守恒、量纲、数值、推导和文献对应；单纯配平并不能证明反应存在。
- 修改 TeX 后按项目配置编译受影响入口，查看引用、图片及溢出警告，并渲染查看受影响 PDF 页面。新增跨页表格、轨道图和结构图要检查可读性。
- 无法编译或核查时，交付可用成果并准确说明未验证的范围；不得把已有 PDF 当成本轮编译成功的证据。
- 简洁说明内容改动、位置、必要的来源与验证结果。仅在仍有实质影响时列待核查项。不要为局部写作附加整章审计或无关重构。

## 与审阅技能的关系

本技能包含完成写作所必需的自检。用户要求独立审阅时再使用 chemistry-lecture-review；不自动启动另一技能或代理。审阅技能未安装也不影响本技能独立工作。
